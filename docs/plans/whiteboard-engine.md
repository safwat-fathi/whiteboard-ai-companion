## What it is

A from-scratch infinite canvas (Canvas 2D), no whiteboard framework. A person and the AI tutor edit the same board through **one op format**, validated by the same zod schemas in `packages/core`, which runs in the browser and on the server.

## Element model

A board is a flat map of elements plus an ordered op log. Nobody writes state directly; everything is an op.

Base fields: `id` (generated by the creator, so later ops can reference it before the ack), `type`, `x y w h` (world units = CSS px at zoom 1), `rotation` (rad, around centre), `z` (fractional index, `fractional-indexing`), `style` (stroke, fill, strokeWidth, opacity, dash), `parentId?`, `locked`, `author {kind: human|agent, id}`, `v` (bumped on every accepted change), `data` (per type).

| Type | `data` | Renders as | Human tool | Tutor tool |
|---|---|---|---|---|
| freehand | points (relative to the box, 0.1 grid), pressure (optional), smoothing, highlighter; width is `style.strokeWidth` | Variable-width outline (`perfect-freehand` 1.2.3), cached `Path2D`; highlighter uses multiply | Pen `P`, Highlighter `Shift+P` | `draw_stroke` (rare) |
| shape | kind (rect, ellipse, diamond, triangle, line, arrow, polygon), radius, label, arrowheads, start/end bindings | `Path2D`; bound arrows re-route | Shape tools `R O D L A` (+ triangle in the picker) | `add_shape`, `connect`, `add_diagram` |
| text | text, font, size, align, `dir` (auto/ltr/rtl), maxWidth | `Intl.Segmenter` + `measureText` layout; `<textarea>` overlay while editing | Text `T` | `add_text` |
| math | latex (≤ 4,000 chars), display, size (8..1000 px/em); the colour is `style.stroke`, as for text | [MathJax SVG → cached bitmap](./math-renderer.md) | Math `M` | `add_math` |
| chart | kind (bar, line, area, pie, **donut**, scatter), title, categories (≤ 50), series (≤ 8, ≤ 200 values, within ±1e15), stacked, axis titles, palette; labels Latin and digits only | In-house `layoutChart` → primitives → bitmap per zoom bucket in the `RenderCache` | Chart `C` (data grid) | `add_chart` |

## Ops, conflicts, undo

- **Four ops:** `add` (full element), `patch` (named fields, dotted paths like `style.fill`), `remove`, `reorder` (new `z`). A **batch** `{batchId, label, ops}` is applied atomically and is the unit of undo.
- **Order:** the server applies batches in arrival order and stamps a board-wide `seq`. Concurrent edits to different fields of one element both survive; the same field resolves by higher `seq`; a patch to a removed element is dropped; only undo brings an element back.
- **Undo:** the store records previous values of every touched field and emits an inverse batch; undo submits it as a **new** batch (append-only). Each person keeps a local stack of inverses of their own changes; if someone changed a field since, undo skips that op and reports how many. **Added:** *Undo this response* reverts all batches of one tutor turn, newest first, with the same skip rule ([jump-to-ai](./jump-to-ai.md)).

## Rendering

- **Pure function** `render(ctx, scene, camera, viewport, platform)`. Same code in the browser and on the server. **Delta F4:** the `platform` adapter supplies `createCanvas`, `rasterizeSvg`, `registerFont`, `measureText`, because offscreen bitmaps, SVG rasterising and fonts are platform calls.
- **Two canvases:** scene (committed elements; repainted only when scene/camera/cache changes) and overlay (selection, handles, snap guides, AI cursor, the stroke in progress, pulses). Both scaled by `devicePixelRatio`, resized with `ResizeObserver`.
- **Camera** `{x, y, zoom}`, zoom 0.05–20, one affine matrix via `setTransform`. **Frame loop:** dirty flag + `requestAnimationFrame`.
- **Spatial index:** R-tree with incremental insert/remove, serving culling, hit-testing, marquee, region queries and free-space search for `placement: "auto"`. `rbush` or in-house (finding F12; decide in M0).
- **Element caches:** expensive elements (math, charts, images, long text) render once to an offscreen bitmap keyed `(element.v, zoom bucket)`; cheap ones draw from a cached `Path2D`.
- **Freehand:** Pointer Events with `getCoalescedEvents()` / `getPredictedEvents()`; samples stored as JSON relative to the box on a 0.1 grid (pressure on a 0.01 grid when a pen reports it; no binary packing, up to 10,000 points); the outline is `perfect-freehand` (smoothing and a variable width); on pointer-up simplify (Ramer–Douglas–Peucker, 0.5 px) and commit one `add`. A touch within 600 ms of a pen event is a palm and starts nothing; the pen's barrel button erases. **Eraser:** whole elements along the drag (tolerance 8 px), one undo step per drag, locked elements skipped, more than 400 hits split into batches of 400. **Charts:** `layoutChart` is pure (primitives, nice ticks, legend, truncation by measured width) and `render()` bakes it into a bitmap per zoom bucket; labels are Latin and digits only so browser and server agree.
- **Hit-testing:** broad phase via R-tree (box padded by 6 screen px / zoom), narrow phase per type; the point is inverse-rotated first for rotated elements (finding F13). The eraser reuses the narrow phase.
- **Fonts (F5):** the same font files (one Arabic-capable OFL font, e.g. Noto Naskh Arabic or IBM Plex Sans Arabic, chosen in S1) are shipped to the page as a web font and registered on the server canvas.
- **Performance targets** (verified in M0): 60 fps pan/zoom with 5,000 visible elements; first ink within one frame; a 20,000-element board opens in < 2 s. If they fail: scene canvas to an `OffscreenCanvas` in a worker; WebGL only if that is not enough. The renderer being pure means neither step changes the element model.

## Interaction

- **Tool contract:** `onPointerDown/Move/Up`, `onKey`, `onCancel` (Esc), and the optional `onPointerLeave` (the pointer left the overlay: drop hover state only, a running gesture holds pointer capture and carries on); tools may draw previews on the overlay, set a hover cursor with `editor.setCursor(css)` (and reset it in `onCancel`) or a default one with `Tool.cursor` (the board cursor precedence is in the tool factory contract below), and end with `editor.commit(batch)`. Tools never mutate the scene directly. A new tool = one file plus its registry entry.
- **Tools:** Select `V` (click, shift-click, marquee; move/resize/rotate; arrows nudge), Hand `H` (open-hand cursor; a mouse drag moves nothing, a touch or pen drag pans) and Space (hold and drag pans from any tool, for a mouse; closed-hand cursor), Pen `P`, Highlighter `Shift+P`, Eraser `E` (whole elements), Shape `R O D L A`, Text `T`, Math `M`, Chart `C`, Image `I`.
- **Input:** Pointer Events for mouse/touch/pen, `touch-action: none`; touch ignored while a pen is in range (palm rejection); pen barrel button = eraser; Space+drag pans from any tool; touch and pen pan with a Hand-tool drag; two-finger pan/pinch is not built (trackpad wheel pan and pinch-zoom work).
- **Selection** is local state (not synced). Resize rules by type: shapes/images scale `w`,`h`; strokes scale points; text scales font size; math, images and charts keep their aspect ratio (`lockedAspect`; resizing a math element changes `data.size` and `w`,`h` in the same batch). Snapping within 6 screen px via the R-tree.
- **Text:** a transparent `<textarea>` positioned over the element gives IME, selection, spellcheck and screen-reader support; direction per element (`auto` picks from the first strong character).
- **Images (M2):** drop, paste or the toolbar picker; PNG, JPEG, WebP, GIF (first frame); SVG is rejected; at most 10 MB per file, long edge downscaled to 4,096 px, EXIF orientation applied, SHA-256 dedupe. Bytes go through the `BlobStore` interface (IndexedDB database `whiteboard-blobs` until `/api/blobs` exists in M3); a board stores only `blobId`s, and a missing blob draws a labelled placeholder. A multi-file drop lands in a grid and is one undo step.
- **Crop (M2):** double-click an image to crop. The uncropped image is shown faded with a bright crop window and 8 handles (7 px hit targets at every zoom); Enter or click-away commits one `patch` (`data.crop`, `x`, `y`, `w`, `h`, so the visible pixels stay put), Esc cancels. The crop clamps to the natural size and to at least 1 source pixel. A *Reset crop* button is not built yet.
- **Camera flight (M2):** `editor.flyTo(target: Rect | Id[], {padding = 48, maxZoom = 2, duration})` resolves `'done'` or `'cancelled'`. It runs in the frame loop with a zoom-out dip that grows with the distance (none when the target is already on screen) and lasts 250 to 1,200 ms; wheel, pointer-down, key-down, a tool change or `setScene` cancel it (the user's camera wins), and a second call replaces the first. `prefers-reduced-motion` jumps instantly. `editor.pulse(target)` draws two expanding outline halos on the overlay for about 1.2 s on ids re-read every frame (it follows a moving element and ends quietly if it is deleted; reduced motion draws one static outline). Flight and pulse are view state: never in ops, undo, snapshots or the saved board.
- **Selection toolbar** gains **Ask AI** (attaches the selection to the chat, see [board-context](./board-context.md)).

## Sync (server-authoritative op log, no CRDT)

JSON over one WebSocket per board; full message shapes in [api](./api.md). The client applies its batch locally and queues it; on a server batch it applies the server's first and replays pending batches (field-level patches make replay rarely change anything). `reject` rolls a batch back. Snapshot + tail on `join`. If two people ever type into the same text block, last write wins (Yjs for text only if that matters later).

## Open items

- R-tree and freehand: leaf library vs in-house (M0, F12).
- Screen-reader outline panel (M7, F13).
- **Group resize semantics (M6, F13; built as PLAN §19 #59, group rotation excepted).** M1 does not resize or rotate groups. `resizeBox` and `rotateTo` return `{}` for lines and arrows (their ends are edited with the select tool's endpoint handles), and the select tool shows resize and rotate handles only for a single unlocked element; a multi-selection can move, nudge and delete. M6 must define: the group's bounding box and handles; how each type scales inside a group (shapes `w`,`h`; strokes scale points; text scales font size; math, charts and images keep aspect ratio; lines and arrows scale their points); how rotation composes (about the group centre, added to each member's own rotation); how arrows bound to members re-route (one batch through `buildBatch`, as for move); and how locked members are handled. The whole gesture stays one batch, so it is one undo step.
- Worker-canvas path: only if S1 misses the budget. M1's measured numbers and the three open decisions are in `apps/web/src/bench/RESULT.md` and the ROADMAP status log.

### Built in M1 (rules later milestones rely on)

- **Rotated hit-testing (F13).** `toLocal` inverse-rotates the point about the element's centre into its unrotated frame, and the narrow phase runs there (filled shapes hit inside; any shape hits within the tolerance of its outline). The tolerance is in world units and stroke-aware: `hitTest(el, p, tolWorld)` accepts a distance of `tolWorld + strokeWidth / 2`, and callers pass `6 / zoom` (6 screen px). Lines and arrows ignore rotation; text hits its stored box, not a layout.
- **Camera convention.** `Camera {x, y, zoom}`: `(x, y)` is the world point at the viewport's top-left, so `screen = (world - (x, y)) * zoom`; zoom is clamped to 0.05–20 in `zoomAt`. It is not the centre-based camera of the S1 spike (the bench converts).
- **Tool factory contract.** `tools/index.ts` maps an id to a factory `(ed: Editor) => Tool`; each `Editor` instantiates every factory once, so tool state lives in the closure and two editors never share any. `Tool.key` is the shortcut (empty means none). `Tool.navigates` marks tools that keep receiving pointer events and can be selected while the editor is read-only (Hand). `Tool.onFrame` runs at the start of every Editor frame (the camera or viewport may have changed; the text overlay re-syncs there). `Tool.onCancel` runs on a tool switch, on `pointercancel`, before every undo/redo and on dispose, and must leave no half-finished gesture (the text tool's commits). `Tool.onPointerLeave` (optional) is called when the pointer leaves the overlay canvas. The board cursor is decided in one place (`Editor.applyCursor`): Space or a pan under way (`grabbing`) > `Editor.setCursor(css)`, a tool's hover cursor (`''` is none; a tool that sets one resets it in `onCancel`) > `Tool.cursor`, the tool's own (`grab` for Hand) > the default arrow. `Editor.setTool` switches tools and `Editor.onToolChange` notifies the toolbar.
- **Text in M1.** A selected text shows only the rotate handle: `drawText` ignores `w`/`h` (the layout owns them), so a resize would break `w`/`h` == layout; scaling a text's font size (the resize rule above) is not built in M1. An open text edit is saved without being committed: `Editor.getSnapshot()` swaps the textarea's draft in (replacing the edited element by id, or appending a new one), so a reload loses nothing typed, while the scene and the undo history only change on commit; a blank draft adds nothing and keeps an edited text's original.
