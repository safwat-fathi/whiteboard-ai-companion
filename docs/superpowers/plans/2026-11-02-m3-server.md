# M3 Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The board lives on a server: it survives restarts, two browser tabs stay in sync, images are stored on disk by content hash, a foreign Origin is refused, and the server can draw a PNG of a board that matches the browser. M3 gate (PLAN §17): *two tabs stay in sync; survives restart; the gate works locally (Origin checks); server PNG matches browser.*

**Architecture:** A new `apps/server` (plain Node `http` + `ws`, **no NestJS**, see R1) owns SQLite (`better-sqlite3`), a disk blob store and the **Board service** (validate → apply with core's `applyBatch` → stamp `seq` → store → broadcast). The Board service and `db/` know nothing about HTTP, so a framework can wrap them later. `apps/web` gains a sync client and an HTTP blob store, used only when `NEXT_PUBLIC_API_BASE` is set; without it the editor stays in M1/M2's local mode, so every existing test and e2e keeps passing untouched. The snapshot renderer is core's `render()` on `@napi-rs/canvas` with the Node math provider.

**Tech Stack:** as M1/M2, plus `better-sqlite3` 13.0.3, `ws` 8.22.1, `tsx` 4.23.15 (dev runner), `@types/ws` 8.18.2, `@types/better-sqlite3`, `@types/node` matching Node 22 (pin exact at install; `allowBuilds: better-sqlite3: true` is already in `pnpm-workspace.yaml`). `pixelmatch` + `pngjs` are already installed for e2e.

**Spec:** [ROADMAP.md](../../ROADMAP.md) M3 · [database](../../plans/database.md) · [api](../../plans/api.md) · [auth-security](../../plans/auth-security.md) · [deployment](../../plans/deployment.md) · [whiteboard-engine](../../plans/whiteboard-engine.md) (Ops, conflicts, Sync) · [tech-stack](../../plans/tech-stack.md).

## Global Constraints

- pnpm only (never npm, yarn, `npx`); exact version pins; `pnpm install --frozen-lockfile` clean; Biome (single quotes, no semicolons); strict TS; Vitest; tests beside sources; one commit per task; stage files explicitly; commits end with `Claude-Session: https://claude.ai/code/session_01MkvK8VyRFHwHP3ZuSHEZFJ`.
- Pragmas on every connection: `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`, `temp_store=MEMORY`. Nothing outside `apps/server/src/db/` imports `better-sqlite3`.
- Migrations: numbered SQL in `apps/server/migrations/`, forward-only, each in a transaction, tracked by `PRAGMA user_version`; before applying a pending migration to an existing DB the file is copied to `DATA_DIR/backups/pre-migrate-<version>.db`.
- `author` is derived by the server from the channel (WebSocket = `human`/`owner`); a client-sent author is ignored. A socket can never produce `agent`.
- Errors use the api.md envelope `{error:{code,message,details}}` and its codes. Logs carry ids, timings and sizes; never keys, board text or book text.
- Blobs: id = SHA-256 hex of the stored bytes, path `DATA_DIR/blobs/<id[0:2]>/<id[2:4]>/<id>`; image types PNG, JPEG, WebP, GIF only, SVG refused, ≤ 10 MB; served with the sniffed type and `X-Content-Type-Options: nosniff`.
- Snapshots: every 500 batches or after 5 minutes of activity, whichever first; ops are kept forever; the server holds the scene of an active board in memory and evicts it after 10 idle minutes.
- The server binds `127.0.0.1` by default; `PUBLIC_ORIGIN` defaults to `http://localhost:3000`; dev web → server is cross-origin (`localhost:3000` → `localhost:4000`).
- No time estimates anywhere in docs. Deploy scripts are written and syntax-checked here, run only on a VPS that does not exist yet.

## Review Focus

Each line is pinned by a test in the task named. Most likely first.

1. **Concurrent edits to one field from two tabs.** A and B patch the same field while each holds the other's batch in flight. Expected: both tabs and the server end with the value the server applied last, no divergence → Tasks 4, 6, 9.
2. **Hostile or broken frames.** Oversized message, invalid JSON, a batch for another board, a batch whose second op fails validation, a 501-op batch, a coordinate of 1e9, a `seq` the client invents. Expected: a `reject` or a closed socket, nothing stored, nothing broadcast, the server keeps serving → Tasks 4, 6.
3. **Restart durability.** Restart with ops only, with a snapshot plus a tail, and after a crash between an append and a snapshot. Expected: the same scene in every case → Tasks 2, 4.
4. **Blob endpoints.** An id like `../../etc/passwd` or `%2e%2e`, an SVG or HTML renamed `.png`, a 0-byte body, 10 MB + 1, two identical uploads at once. Expected: no filesystem access outside `blobs/`, 400/404/413 with the envelope, one file for the duplicates → Tasks 3, 7.
5. **Origin edge cases.** Missing Origin, `null`, `http://localhost:3000/` with a slash, another port, a WebSocket upgrade from a foreign page, a CORS preflight from a foreign origin. Expected: 403 `forbidden_origin` for all but the exact origin; no CORS headers for others → Tasks 5, 6.
6. **Client ahead of the server** (the DB was wiped) and a reconnect after a long gap. Expected: the server sends a full snapshot, the client replaces its scene → Tasks 4, 9.

### Task 4: Board service

**Files:** Create `apps/server/src/board-service.ts`, `src/board-service.test.ts`.

**Interfaces:**
- Consumes: Task 2's `BoardsDb`; core `applyBatch`, `createScene`, `bounds`, `validateBatch`, `Element`, `Batch`.
- Produces:
  - `type Author = {kind: 'human'|'agent'; id: string}`; `type Broadcast = {seq: number; batch: Batch; author: Author; turnId?: string; bounds: Bounds | null}`.
  - `class BoardService` — `constructor(db: BoardsDb, o?: {now?: () => number; snapshotEvery?: number; snapshotAfterMs?: number; idleEvictMs?: number})`:
    - `createBoard(title: string, scope?: Scope): BoardRow`, `getBoard`, `listBoards`, `updateBoard`, `deleteBoard` (delegates; deleting closes live subscribers' view by evicting the scene);
    - `submit(boardId: string, batch: unknown, author: Author, turnId?: string): {seq: number; noop: boolean; broadcast: Broadcast | null}`: validates (`validateBatch`), applies to the in-memory scene with `applyBatch` on a loaded board, computes `bounds` (after-state of added/patched, before-state of removed), `appendBatch`, notifies subscribers, snapshots when due. ### Task 6: WebSocket gateway

**Files:** Create `apps/server/src/gateway.ts`, `src/gateway.test.ts`; Modify `src/main.ts`, `src/http.ts` (exports the `server` for `attachGateway`).

**Interfaces:**
- Consumes: Task 4's `BoardService`, Task 5's `checkOrigin`.
- Produces: `attachGateway(server: http.Server, deps: {boards: BoardService; config: Config}): {close(): Promise<void>}` using `ws` with `noServer`, path `/ws?boardId=<id>`, `maxPayload` 1 MB, a 30 s ping/pong that terminates dead sockets.
- Messages (JSON, zod-validated, from api.md): C→S `join {boardId, fromSeq}`, `ops {clientSeq, batch}`; S→C `sync {headSeq, snapshot?: {seq, scene}, ops: Broadcast[]}` (the answer to `join`), `ack {clientSeq, seq}`, `ops {seq, batch, author, turnId?, bounds}` to every **other** socket on the board, `reject {clientSeq, reason: {code, message, details?}}`.
