# M4 Library: task plan

## Context

M0–M3 are built (M3 gate green on `m3-server`, working tree clean after the owner's commit). M4 turns an uploaded PDF into searchable, citable pages: upload, estimate and preview, extract, structure, chunk, embed, summarise, hybrid search, library UI and a source viewer. The M4 gate (PLAN §17) is **retrieval eval met on a real book**: the expected page in the top 8 for ≥ 80% of the questions in `eval/*.jsonl`.

**Owner decisions already taken:** Muse Spark OCR validated for Arabic and CK-12. R3 (`mistral-ocr` via OpenRouter) stays an **opt-in paid rung**. No pricing or token tracking for Meta models. Implementation starts on a **fresh branch** off `m3-server`, no commits until implementation begins.

**Step 0 (first action after approval):** `git switch -c m4-library` from `m3-server`, then copy this plan to `docs/superpowers/plans/2026-11-03-m4-library.md` (M2/M3 plans live there). `m4a-library-core` is stale (points at `1dbd189`) and stays untouched.

## Facts the plan rests on (verified)

- `0001_init.sql` already has `books`, `book_sections`, `book_pages`, `book_chunks`, `book_chunks_fts` with its three triggers, `spend`, `settings`. **No migration needed** unless a task finds a missing column.
- DB code goes in `apps/server/src/db/*.ts` (`createBoardsDb` pattern, exported from `db/index.ts`); nothing else imports `better-sqlite3`. HTTP is hand-routed on `seg[]` in `apps/server/src/http.ts` (helpers `parse`, `readJson`, `readBody`, `send`, `ApiError`); every non-GET needs `Origin == PUBLIC_ORIGIN`. `ApiError` already has `ingest_failed`, `budget_exceeded`, `upstream_error`. `Config` is key-presence only.
- The disk blob store is image-only (`sniffMime`, 10 MB). PDFs need their own streamed put; `books.file_blob` still references `blobs(id)`, same hash layout (`createDiskBlobStore().path(id)`).
- Server has no `pdfjs-dist` or `pdf-lib`. Spikes validated `pdfjs-dist` 5.7.284 (legacy build) and `pdf-lib` 1.17.1. `@napi-rs/canvas` is already a server dependency.
- Reusable spike code: `spikes/s2-ingestion/r1.ts` (outline, `getPageLabels`, density, `MATHCH`, PUA strip), `slice.ts` (`copyPages`), `ocr.ts` (R3/R4 request shapes); `spikes/s4-search/topk.ts` (exact top-k), `recall.ts` (`normaliseText`, `ftsQuery`, RRF k=60, bge-m3 retry on 429/5xx).
- Real books (`spikes/books/`, gitignored output): CK-12 652 pp (12 math-dense, outline 12, custom page labels), Algebra 1 700 pp (44 math-dense, outline 83), Arabic scan 383 pp (**all 383 pages have no text layer** → all R4). Eval: `eval/{ck12,alg1,arabic}.jsonl` (`{q, pages[], numbering?: "printed"}`; CK-12 is printed numbering).
- Muse: 8.5–13 s per page, reasoning tokens ate the 4,000-token cap on Arabic p. 78. Image goes as `image_url` in a **user** message. Arabic gate book at concurrency 4 ≈ 20 min.

## Rulings **[my call]**, override any

| R1 | **Plain `fetch` for every provider call in M4** (Meta chat for R4 and summaries, OpenRouter for embeddings and R3), one module `library/providers.ts` behind an injectable `Providers` interface. R2 stays dropped. | Matches the owner's validation and S2's thresholds. | Constants. |
| R4 | **R4 hardening:** concurrency 4, `max_tokens` 12,000, retry 429/5xx with backoff; on `finish_reason: 'length'` retry once at 2×, then keep the partial text and list the page in `ingest_method.warnings`. | Muse reasoning tokens; page 78 hit the cap. | Constants. |

| R6 | **Job = in-process sequential queue + worker thread.** The pipeline is a plain async function `runIngest(bookId, deps)` (tested inline); `worker.ts` is a thin entry that opens its own DB connection. Each stage is resumable from `book_pages` / `book_chunks`. If `new Worker(.ts)` fails under tsx, fall back to running inline on the main thread and say so. | PDF parsing must not block the WebSocket; inline testing keeps it deterministic. | Worker wiring only. |
| R7 | **Sections:** PDF outline when present, else fixed 20-page sections titled "Pages a–b". Font-size heading detection and LLM TOC inference are **not built** (library-ingestion.md lists them as fallbacks). | The Arabic scan has no usable outline; fixed sections give scopes and summaries today. | Add the fallbacks when a book needs them. |

| R9 | **Search without `OPENROUTER_API_KEY` degrades to keyword-only** and reports `mode: 'keyword'`. Across-library search runs per book and keeps the top `k` by fused score. | Never crash the UI for a missing key. | None. |

## Global constraints

pnpm only, exact version pins, `pnpm install --frozen-lockfile` clean; Biome (single quotes, no semicolons); strict TS; Vitest beside sources; **one commit per task**, stage files explicitly, attribution line from the session reminder; no time estimates in docs; errors use the api.md envelope; logs carry ids, timings and sizes, never keys or book text. Treat PDFs and book text as untrusted: `pdfjs` with `isEvalSupported: false`, no network, raster size capped (≤ 4,000 px a side), book ids in paths are DB-issued SHA-256 hex, never client paths.

## Review focus (each pinned by a test in the task named)

1. **Kill mid-run, re-run** finishes without redoing finished pages or duplicating chunks → T9, T10.
2. **Hostile uploads:** a non-PDF renamed `.pdf`, 200 MB + 1, truncated, encrypted, 2,001 pages, a 0-byte body, a path-looking id → T3, T12.
3. **Truncated Muse page** (`finish_reason: length`) is retried once, then kept with a warning → T7, T9.
4. **No chunk crosses an equation, table or fence** → T6.
5. **Arabic search:** a query with harakat or alef variants finds the page → T6, T8.
6. **Write contention:** ingest worker inserting chunks while the main thread appends board batches: no `SQLITE_BUSY`, appends stay fast → T10.
7. **Paid rung past the daily cap** is refused before any call → T9, T12.

## Tasks

### 4a: ingestion core (needs only M3's persistence layer; M5 can start after Task 11)

**T1 Deps, config, providers skeleton.** Add `pdfjs-dist` and `pdf-lib` to `apps/server` (pin the versions the spikes proved); root scripts `ingest` and `eval:retrieval` (`pnpm --filter @whiteboard/server …` with `--env-file-if-exists=../../.env`). `config.ts` gains `metaBaseUrl`, `cheapModel`, `visionModel`, `embedModel`, `embedDims`, `dailyBudgetUsd` (all defaults from `.env.example`; keys stay presence-only; secrets are passed to `createProviders(env)` from `main.ts`, never into `Config`). `providers.ts`: `Providers = {embed(texts), transcribePage(png, opts), ocrPages(pdfSlice), complete(prompt, opts)}`, `retryFetch` (429/5xx, backoff 1.5 s doubling, 4 tries), `stubProviders()` (hash-based deterministic vectors, canned text). *Tests:* config defaults and bad values; `retryFetch` retries 429 then succeeds, gives up with `upstream_error`; stub embeddings are unit length and deterministic.

**T2 `db/books.ts`.** `createBooksDb(db)`: `createBook`, `getBook`, `listBooks`, `setStatus(id, status, progress?, error?)`, `setMethods`, `upsertPage` (idempotent), `pagesDone(id)`, `insertSections(tree)` returning ids, `insertChunks(rows)` in transactions ≤ 200 rows, `setEmbedding(chunkId, vec)`, `chunksOf(bookId)`, `ftsSearch(bookId, query, sectionIds?, limit)`, `addSpend`, `spentSince(ts)`, `deleteBook` (cascade; returns the blob id if no other book uses it). *Tests:* round trips; FTS trigger finds a chunk and deleting removes it; cascade leaves `foreign_key_check` empty; idempotent page upsert; blob id returned only when unreferenced; `spentSince` sums correctly.

**T3 PDF file store.** `files.ts`: `putPdf(stream, {dataDir, db, maxBytes=200 MiB})` writes a temp file under `DATA_DIR/tmp`, hashes while streaming, checks `%PDF-` in the first bytes, renames to the blob path, inserts the `blobs` row with `application/pdf`. *Tests:* a valid PDF stores byte-equal and dedupes; HTML renamed `.pdf`, 0 bytes → `validation_failed`; `max + 1` → `payload_too_large` with nothing left in `tmp`; two concurrent identical uploads give one file.

**T4 pdfjs wrapper and routing (R1).** `pdf.ts`: `openPdf(bytes)` → `{numPages, outline, labels, pageText(n), renderPage(n, w)}`; `cleanText` strips `\x00–\x1F` and PUA `–`; `isEvalSupported: false`; encrypted or corrupt → `ingest_failed`; `numPages > 2000` → `ingest_failed` with the limit. `route.ts`: `pageStats(text)` and `routePages(stats)` with the R3 constants; `estimate(book)` returns page counts per rung and the embedding cost. *Tests:* a tiny fixture PDF (generated with `pdf-lib` in the test) gives the text, labels and outline; cleanText removes seeded control and PUA chars; routing puts a 10-char page and a `=+×÷`-heavy page on R4 and a prose page on R1; **a script run on the three real books prints the R4 page counts and they match the S2 numbers (CK-12 ~12, Alg1 ~44, Arabic 383)** (record in the commit message, not a test).

**T5 Structure.** `structure.ts`: outline → `book_sections` tree with `page_start`/`page_end` (end = next sibling's start − 1, last = last page), levels, `ord`; fallback to 20-page sections; printed labels come from `pdf.labels`. *Tests:* nested outline gives correct ranges and levels; outline entries pointing past the last page are clamped; no outline gives ⌈pages/20⌉ sections; CK-12-style roman-then-arabic labels map `page_index → label`.

**T6 Chunker and normalisation.** `chunk.ts`: `normaliseText` and `ftsQuery` lifted from `spikes/s4-search/recall.ts`; `chunkPages(pages, sections)` heading-aware, 400–800 tokens (`ceil(chars/4)`), ~12% overlap, atomic blocks (`$$…$$`, `$…$` pairs, tables, code fences, figure captions are never split), each chunk keeps `section_id`, `heading_path`, page range, `cite_label` ("p. {label}"); embedded text is `heading_path + "\n" + chunk`. *Tests:* a chunk boundary never falls inside `$$…$$` or a table; overlap present; page range and label correct across a page break; `normaliseText` folds harakat, alef variants, ta marbuta, Arabic-Indic digits; `ftsQuery` quotes tokens; property-style: concatenating chunk text without overlap equals the input.

**T7 Real providers.** Implement over `retryFetch`: `embed` → OpenRouter `/api/v1/embeddings` (batched, `data_collection: 'deny'`, L2-normalise, check `dims == embedDims`), `transcribePage` → Meta `/chat/completions` (prompt from `ocr.ts`, PNG as `image_url`, R4 `max_tokens` handling), `ocrPages` → OpenRouter `file-parser` `mistral-ocr` with `pdf-lib` `copyPages` slices (per-page split of the `<file>` content as in the S2 notes), `complete` → Meta chat for summaries. *Tests with a local `http.createServer` fake:* request shapes (auth header, body fields), batching, 429 retry, truncated response triggers the 2× retry then returns `{truncated: true}`, a dims mismatch throws. No live calls in unit tests.

**T8 Search.** `search.ts`: `topK` from the spike (4 accumulators, `dims % 4` throws), `VectorCache` (per-book `Float32Array`, LRU 512 MB, `invalidate(bookId)`), `searchBook({bookId?, sectionIds?, query, k=8, neighbors?})`: scope filter → FTS5 bm25 top 30 + vector top 30 → RRF (k=60) → top k → optional ±1 neighbours; keyword-only when embedding is unavailable (R9). *Tests:* RRF ordering on a hand-built set; scope filter respects `sectionIds`; neighbours add adjacent chunks once; Arabic query with harakat finds the undecorated chunk; cache invalidation after re-embed; library-wide search merges two books; keyword-only mode reports `mode`.

**T9 Ingest pipeline.** `ingest.ts` `runIngest(bookId, deps)`: `extracting` (route, R1 inline, R4/R3 per R3/R4 rulings, `upsertPage` per page, progress) → `structuring` → chunk → `embedding` (batches, `addSpend`, daily-cap check before starting) → `summarising` (R8) → `ready`; any throw sets `failed` with the stage in `error`; resume skips pages already in `book_pages` and chunks already embedded. *Tests (stub providers):* happy path ends `ready` with chunks, FTS rows, embeddings and per-page `method`; **kill after N pages (throw from the stub) then re-run: finished pages are not re-requested and chunks are not duplicated**; truncated R4 page lands in `warnings`; R3 chosen with a daily cap below the estimate → `budget_exceeded` and zero provider calls; embeddings write one `spend` row per batch; summary failure leaves `ready` plus a note; `failed` keeps partial pages.

**T10 Queue, worker, CLI, contention.** `queue.ts` (sequential, one job at a time), `worker.ts` (opens its own connection via `openDatabase`, runs `runIngest`, posts progress), `cli.ts` (`pnpm ingest <file.pdf> [--title] [--r3 p1-p9]`, same code path as upload, prints the estimate then runs). *Tests:* queue runs jobs in order and survives a failing job; worker wiring test runs a tiny book end to end; **load test: worker inserting ~5,000 chunks while the main thread appends 200 board batches: no `SQLITE_BUSY`, board append p95 under a generous bound**; CLI refuses a non-PDF.

**T11 Eval runner and the 4a gate.** `eval.ts` (`pnpm eval:retrieval -- --book <id|title> --eval eval/ck12.jsonl`): maps `numbering: printed` through `book_pages.label`, reports per book recall@8 and MRR for keyword, vector, hybrid and hybrid+neighbours, exits non-zero when hybrid@8 < 80%. *Tests:* a tiny ingested stub book with known answers gives expected recall and the printed-label mapping; below-target exits 1. **Live gate (owner-visible, real calls, OpenRouter embeddings ≈ cents, Muse unpriced):** ingest CK-12, Algebra 1 and the Arabic scan with the CLI, run the three evals, paste the numbers into the status log. **Checkpoint: stop here, report numbers, then continue to 4b.** If the eval misses, follow the documented ladder: neighbours → `qwen3-embedding-8b` → chunk context → reranker (no new work unless needed).

### 4b: REST, UI, viewer (needs M3's server and web shell)

**T12 REST routes.** `http-books.ts` wired from `http.ts`: `POST /api/books?title=` (R2), `GET /api/books`, `GET /api/books/:id`, `GET …/estimate`, `POST …/preview {pages}` (R1 and R4 text beside the page image URL, cap 3 pages, no spend rows), `POST …/index {methods?}` (daily-cap check, 202, enqueue), `POST …/retry`, `DELETE`, `GET …/outline`, `GET …/file` (range requests, `application/pdf`, `nosniff`, path from the DB blob id), `GET …/pages/:n` (text, label, method), `GET …/pages/:n/image?w=` (raster cached at `DATA_DIR/cache/pages/<book>/<n>@<w>.png`, w clamped 256–2048), `GET …/chunks/:chunkId`, `POST /api/search {query, bookId?, sectionIds?, k?, neighbors?}`. `main.ts` builds providers, queue and worker; `/api/health` already reports key presence. *Tests (contract per route, valid/invalid body, error codes, Origin on every non-GET):* upload→estimate→preview→index→poll `ready`→search→chunk→page→file range (206 and 416); estimate and preview write no `spend` rows and change no status; hostile upload cases from Review focus 2; `index` with R3 over the cap → 429 `budget_exceeded` and nothing queued; `…/file` for an unknown or non-hex id → 404; delete cascades and removes cache files.

**T13 Library UI.** `/library`: dropzone (PDF only, client-side size check), book cards (title, pages, status and progress by polling `GET /api/books/:id`, method, error + Retry, delete), estimate dialog with the routing summary and an explicit **Index** button (the paid-rung confirmation; R3 shown only as an opt-in checkbox per range). `/library/[bookId]`: outline tree with page ranges and summary preview, search box (calls `/api/search`, shows `cite_label`, heading path, snippet), **Study this** creates a board with scope `{kind:'book', bookId}` (and chapters when sections are ticked) via the existing `POST /api/boards`, then opens it. Server mode only (needs `NEXT_PUBLIC_API_BASE`); local mode shows a notice. *Tests:* vitest for the API client and the status polling reducer; component logic that is pure (scope builder from ticked sections).

**T14 Source page viewer.** `SourceViewer.tsx` (`pdfjs-dist` in `apps/web`, range requests from `/api/books/:id/file`; scanned pages show the cached raster): opens at a page, previous/next, shows the printed label; mounted on the Book page when a search hit or outline entry is clicked. It is exported as a component with `{bookId, page}` props so M5 mounts it as the dock's Source tab. *Tests:* pure helpers (page clamp, label display); the e2e below drives it.

**T15 Gate script, docs, status.** `e2e-server/m4-gate.spec.ts` (ports 3100/4100, temp `DATA_DIR`, stub providers via an env switch so it is deterministic and free): upload a small fixture PDF in the UI, watch progress to `ready`, browse the outline, search, click the hit, the viewer shows the cited page; kill and restart the server mid-ingest then Retry completes; a foreign Origin upload is 403. Docs: PLAN §19 (#34+) rulings R1–R10; `api.md` (raw upload, estimate/preview shapes, search response); `library-ingestion.md` (R4 default, Muse caps, R7 deviation, R10); `testing-spikes.md` (Library results, numbers from T11); README and `tech-stack.md` scripts; ROADMAP M4 status and status-log row. List the owner's manual demo (upload a real book, watch progress, browse, search, open the cited page) as theirs.
