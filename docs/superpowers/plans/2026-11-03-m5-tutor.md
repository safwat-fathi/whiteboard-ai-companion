## Facts the plan rests on (verified in this session)

- **Server seams.** `BoardService.submit(boardId, input, author, turnId?)` (`board-service.ts:114`) already takes an agent author, validates, stamps `author` on every `add`, computes `bounds`, stores `turn_id/label/bounds/touched_ids`, and broadcasts to all sockets (`sender` null). It computes `applyBatch(...).inverse` then **discards it**; `board_ops` has **no inverse column**; there is **no edit-rights guard**, **no turn lock**, no `opsByTurn` query. `0001_init.sql` already has `messages`, `settings`, `spend`; `books.addSpend` accepts `kind:'turn'`, `books.spentSince(ts)` is the daily-cap sum. No db module for messages or settings.
- **HTTP.** Hand-routed on `seg[]` in `http.ts`; every non-GET needs `Origin == PUBLIC_ORIGIN`. The library mounts as a pluggable handler (`createLibraryRoutes`, `http.ts:268`); a tutor handler copies that. `sendError` destroys the response once headers are sent, so **`turn_busy` / `budget_exceeded` must throw before `writeHead`**. `GET /api/books/:id/chunks/:chunkId` exists. The embed closure for search is inline in `http-books.ts:297-318` and must be factored out.
- **Config** has no tutor fields. `TUTOR_MODEL`, `TUTOR_MODEL_AR`, `TUTOR_FALLBACK_MODEL`, `MAX_STEPS`, `MAX_TURN_COST_USD`, `CHAPTER_STUFF_MAX_TOKENS`, `SNAPSHOT_ADAPTER`, `TUTOR_STUB` are in `.env.example` and read by nothing. `INGEST_STUB` is read straight from `process.env` in `main.ts:33`.
- **AI SDK.** `ai@7.0.159` and `@ai-sdk/openai-compatible@3.0.82` are already in the lockfile (spike S3); the docs' "2.x" is wrong. `ai` exports `streamText`, `isStepCount`, `createUIMessageStream`, `pipeUIMessageStreamToResponse`, `DefaultChatTransport`, `AbstractChat`, `readUIMessageStream`; `ai/test` ships `MockLanguageModelV3`, `simulateReadableStream`. `@ai-sdk/react` is **not** in the lockfile. No dagre or elk in the lockfile.
- **Meta API (S3).** Tool loop and usage streaming pass on `muse-spark-1.3`; **image parts in `role:'tool'` are rejected (400)**; prefix caching is automatic; 600–1,200 reasoning tokens and **15–25 s per step**; Arabic follows the "answer in the user's language, math as `$…$`" rule.
- **Core.** `UndoManager.fromJSON/undo()` already has the conflict rule we need: inverse ops whose target changed since `original` are dropped and counted (`undo.ts` `filter`). `ImageDataSchema` has no `source`. Elements are `shape | text | math | image` only (no freehand until M6). `render(ctx, scene, camera, viewport, platform, opts)` is synchronous and reads math/images through `peek`, so a picture builder must prefetch first; `export.ts:80-175` (`renderBoardPng`) is the template and is the server-side `get_snapshot`.
- **Web.** `app/page.tsx` is one client component; host is `fixed inset:0` (a dock means shrinking `host`; the editor's `ResizeObserver` handles it). No `/boards/:id` route; board id lives in `localStorage`. `Toolbar`/`Notices` are viewport-centred. Editor exposes `selection` (a `Set`, mutated directly by `select.ts`, **no change event**), `flyTo`, `pulse`, `index.pick/search`, `worldToClient`, `getSnapshot`. `sync.ts:134` **drops `author`, `turnId` and `bounds`** from `ops` broadcasts. `SourceViewer({api, bookId, page, pages, onPage})` is already written for reuse; the scope picker is inline in `[bookId]/page.tsx`; `createLibraryApi` has no `getBoard`. No selection toolbar, no AI tag anywhere. `apps/web/AGENTS.md`: **read `node_modules/next/dist/docs/01-app` before writing route code** (Next 16.4).
- **Tests.** `boot()` in `http-test-utils.ts` starts a real server over a temp DB (no gateway); `gateway.test.ts` has its own boot with `ws` clients. `e2e-server/helpers/server.ts` `startServer({dataDir, port, env})` runs the real server (no `.env`). `window.__editor` is dev-only; owner's `next dev` holds :3000 and :4000.
- **Not in the schema/code and needed:** `image.source`, `board_ops.inverse`, tutor config, messages/settings db modules.
